# Стек и форма доставки страницы

Type: grilling
Status: resolved
Blocked by: —
Map: ../map.md

## Question

Калькулятор открывается в браузере с телефона. Чем это физически является:

- **Один статичный HTML-файл** без сборки — открывается локально, кидается в мессенджер, живёт вечно.
- **Artifact на claude.ai** — ссылка, открывается с телефона без хостинга.
- **Проект со сборкой** (Vite и подобное) с расчётом на то, что потом появятся другие калькуляторы.

Что решить помимо самого стека:

- Нужен ли хостинг и по какой ссылке это открывается на телефоне.
- Сохраняется ли расчёт между открытиями страницы, и если да — в чём (адресная строка с параметрами, локальное хранилище браузера, никак).
- Работает ли страница офлайн: сценарий «сижу вяжу, интернета нет».
- Насколько решение переживёт появление второго калькулятора — не проектируя под него, но и не отрезая путь.

Назначение карты — один калькулятор мыска, поэтому фундамент под семейство здесь сознательно не строим.

## Answer

Разобрано вживую. Форма доставки — **сайт-статика на GitHub Pages**, собранный проект на Vite + Vue 3 +
TypeScript + Tailwind 4.

1. **Стек.** Vite + Vue 3 (Composition API, SFC) + TypeScript + Tailwind 4 через плагин
   `@tailwindcss/vite` и `@import "tailwindcss"`. Роутера нет — страница одна. Pinia нет — состояние
   живёт в одном composable. Тесты — Vitest, только на расчётном ядре; компоненты не тестируем.
   Принятое следствие сборки: через несколько лет проект оживёт только пересборкой `node_modules`,
   в отличие от плоского файла. Это цена, а не недосмотр.
2. **Хостинг и адрес.** Публичный репозиторий `fey/knitting-tools`, GitHub Pages, project site по адресу
   `https://fey.github.io/knitting-tools/` (корень домена занят Jekyll-блогом). Деплой — официальный
   Pages-workflow на Actions (`configure-pages` → `upload-pages-artifact` → `deploy-pages`) по push
   в `main`, source = GitHub Actions, без ветки `gh-pages`. В `vite.config` — `base: '/knitting-tools/'`.
   Репозиторий переименован из `knitting_tools` до появления remote: дефис вместо подчёркивания в URL.
3. **Офлайн — мягкий.** Требование звучит как «ссылку открыли дома, вкладка висит весь вечер, дальше
   считает без сети». Расчёт целиком в браузере, так что это выполняется само. Service worker, manifest
   и настоящий офлайн-первый заход в v1 не делаем.
4. **Хранение расчёта.** Два вида состояния живут в двух разных местах.
   - **Параметры** (начальные петли, конечные, кромка, ритм) — в hash-фрагменте URL
     (`#s=60&e=20&k=1&r=1x11`), переписывается живьём через `history.replaceState`. Hash, а не query:
     на сервер не уходит, и не путается с тем, как Pages отдаёт 404 на несуществующий путь. Побочная
     выгода — SPA-роутинга нет, значит и костыля `404.html` не нужно.
   - **Прогресс ряда** — в `localStorage`, **одной записью** `{ paramsKey, row }`, где `paramsKey` —
     те же значения, что в hash. Параметры на экране не совпали с `paramsKey` — прогресса нет, схема
     чистая. Запись появляется только при явной отметке ряда, поэтому кручение ритма мусора не создаёт.
   - **Запись ритма расширена в тикете «Дефолты полей и пресеты ритма»**: `r=` несёт либо имя пресета
     (`even`, `accel`, `thirds`, `ramp`), либо сегменты своего ритма через запятую в виде
     `интервалxповторы` (`r=1x4,0x7`). Пример `r=1x11` выше остаётся валидным — это свой ритм одним
     сегментом.
   - **Приоритет при загрузке**: hash → `localStorage` → дефолты. Иначе присланная ссылка молча покажет
     чужой расчёт.
   - Нужна ли отметка ряда вообще — вопрос тикета «Отметка текущего ряда на схеме». Здесь
     зарезервировано место под неё, а не принята фича. Если тикет решит «не нужна», в `localStorage`
     не пишется ничего и контракт не мешает.
5. **Поделиться.** Кнопка, зовущая `navigator.share()` (на Pages есть HTTPS, значит на телефоне
   открывается родной системный шит) с фолбэком на копирование в буфер там, где API нет. В шит уходит
   не только `url`, но и `text` вида «Мысок: 60 → 20 петель, убавки через ряд, 19 рядов» — сообщение
   читается даже без перехода по ссылке. **Число в примере исправлено при разборе тикета «Дефолты
   полей и пресеты ритма»**: при 60 → 20 выходит 10 убавочных рядов и 19 рядов всего (`2N − 1`),
   а стоявшее здесь «21 ряд» — ответ для 60 → 16 из пункта 7, случайно приложенный к другим петлям.
   **Прогресс в ссылку не попадает никогда**: делятся расчётом,
   а не тем, докуда довязано.
6. **Раскладка проекта.** `src/calculators/toe/` с ядром и компонентами внутри, общее — в `src/shared/`.
   Каталоги разведены под будущие калькуляторы, но роутера сегодня нет и витрины разделов нет: на корне
   сайта сам калькулятор мыска. Известный конфликт на будущее: `vue-router` в hash-режиме занял бы тот
   же hash, где лежат параметры расчёта, поэтому со вторым калькулятором роутер пойдёт в history-режиме
   (и потребует копию `index.html` в `404.html`) либо параметры переедут в query.
7. **Расчётное ядро.** Логика поднимается из прототипа `toe-visualization.html` в
   `src/calculators/toe/core/` как чистый TypeScript без единого импорта из Vue. Проверенный случай
   оттуда — 60 → 16 при убавках через ряд даёт 11 убавочных рядов и 21 ряд всего, половина уходит
   с 30 до 8 — становится первым тестом Vitest. Это же ядро обслуживает ограничение карты: число рядов
   мыска хранится в нём самостоятельной величиной.
8. **Схема — декларативный SVG.** Компонент проходит `v-for` по рядам и клеткам, пересчёт при кручении
   ритма идёт реактивностью. Императивный рендер в `onMounted` отвергнут: со схемой-чёрным-ящиком Vue
   остался бы ради четырёх полей ввода. Геометрия значков «Вязаный.рф» и размер клетки (22px, кнопки
   −/+) — константами в `core/`, а не числами в Tailwind-классах: иначе спека не сможет записать их
   единым источником.

### Ход обсуждения

- **Требования спрашивались до формы.** Первый раунд — распространение, офлайн и что переживает
  закрытие вкладки; форма, хостинг и механизм хранения выводились из ответов, а не наоборот.
- **Artifact на claude.ai отпал** на вопросе об офлайне: жёсткого требования «открывается без сети
  с нуля» не оказалось, но и мягкого хватило, чтобы предпочесть собственный адрес.
- **Рекомендация «плоские файлы без сборки» отклонена пользователем в пользу Vue + Tailwind 4.**
  Довод против сборки (`node_modules` через три года) озвучен и принят как известная цена.
- **Строка карты про фундамент под семейство пересмотрена.** Пользователь: «в будущем можем другие
  калькуляторы тут делать и разводить по разделам/подстраницам». Семейство признано будущим этого
  репозитория, но фундамент под него сегодня всё равно не строится — отсюда каталоги без роутера.
- **Найдено, что корень `fey.github.io` занят** живым Jekyll-блогом со статьями, Pages включён.
  Значит адрес в любом случае project site, и имя репозитория попадает в URL — отсюда переименование
  на дефис, пока remote ещё не создан.
- **Кнопка «Поделиться» предложена пользователем** и закрыла дыру в исходной рекомендации: на телефоне
  адресной строки почти не видно, поэтому живой hash там невидим, и весь выигрыш даёт `navigator.share()`.
  Оставлены оба: hash как бесплатная закладка, кнопка как основной путь.
- **Вопрос о трекере разобран, но записан не сюда.** Пользователь спросил про GitHub Issues, затем про
  beads. Решение — переехать на beads целиком, отдельным заходом; оно правит строку «Трекер» в `## Notes`
  карты, а не этот тикет. Опора: `bd` v1.0.4 уже обкатан в другом проекте автора. Сам `wayfinder`
  объявляет расположение карты и блокировок tracker-specific, а конвенцию `Blocked by:` в теле —
  фолбэком для трекеров без нативных зависимостей. Цена переезда названа: тикеты перестают читаться глазами, `.beads/issues.jsonl` —
  нечитаемый пассивный экспорт.
