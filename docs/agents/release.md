# Выкатка и релизы

## Выкатка

**«Выкатывай» значит довести сделанное до живой страницы.** Работа уходит в `main`, Actions
собирает и деплоит — и на Pages лежит она. Слово мастера — разрешение на мерж и деплой, отдельно
подтверждать нечего. Путь до `main` один: ветка, PR, squash-мерж (`gh pr merge --squash`) — прогон на PR проверяет сборку
до того, как она уедет на прод. Деплоит сам push в `main`, релиз от выкатки не зависит
(ниже, «Релизы»). Уезжает работа сессии — чужие правки, лежащие в рабочей копии,
остаются на месте.

Слово приходит после показа на стенде. Перед мержем — то, чего зелёный прогон не обещает:
**экран правился — базлайны `screens` и карточка `og.png` пересняты** (CLAUDE.md, «Тесты», и
`README.md`), в CI ни те, ни другая не гоняются.

**Выкачено — это зелёный прогон и живая страница, а не смерженный PR:** пока Actions собирает,
на проде лежит прежнее. Прогон ждут по коммиту — `gh run watch` без аргумента в неинтерактивном
прогоне просит id:

```
gh run watch --exit-status $(gh run list --commit "$(git rev-parse origin/main)" -L1 --json databaseId --jq '.[0].databaseId')
```

Список пуст — прогон ещё не завёлся, повторить. Дальше открыть живую страницу, убедиться, что
правка на ней, и дать в отчёте адрес — с hash того расчёта, если правился калькулятор.

## Релизы

Релиз — это номер версии и заметки для мастера о том, что изменилось на странице. Выкатку он
не заменяет: к моменту релиза всё, что в нём описано, уже лежит на живой странице.

Собирает релизы release-please (`.github/workflows/release.yml`, конфиг
`release-please-config.json`). На каждый push в `main` он держит открытым PR
«chore: Релиз X.Y.Z»: версия в `package.json`, запись в `CHANGELOG.md`, заметки из `feat`, `fix`
и `perf`. Мерж этого PR ставит тег `vX.Y.Z` и публикует релиз на GitHub. Если с прошлого релиза
в `main` были только служебные коммиты, PR не появится.

- **Версия** — semver от типов коммитов: `feat` поднимает минор, `fix` и `perf` — патч, `!` —
  мажор. Отсчёт идёт от `1.0.0` — это страница на момент подключения релизов.
- **«Выпускай релиз» — отдельное слово мастера.** Оно значит смержить PR релиза и убедиться,
  что релиз появился на <https://github.com/fey/knitting-tools/releases>. Слово «выкатывай»
  PR релиза не трогает.
- **Заметки пишутся заголовками коммитов, а не правкой PR релиза.** Release-please
  пересобирает этот PR на каждый push в `main`, и ручная правка в нём продержится только
  до следующего push.
